# План доработки по техническому заданию

## Текущее состояние

Уже реализованы Android-клиент на Kotlin и Jetpack Compose, выбор WAV через Storage Access Framework,
отправка файла в FastAPI, отображение вероятности, PostgreSQL для истории, Redis-кэш по SHA-256,
Docker Compose, healthcheck зависимостей и анимированная заставка FAITH.

Backend построен как синхронный REST API. Анализ выполняется непосредственно в HTTP-запросе.
Текущий анализатор является детерминированным прототипом на акустических признаках NumPy, а не
обученной и измеренной ML-моделью. Android-клиент пока не разделён на MVVM-слои.

## Расхождения с техническим заданием

### Приоритет 1

- отсутствовали строковые ресурсы RU/EN и первый выбор языка;
- отсутствуют запись с микрофона и предварительный просмотр аудио;
- главный экран и результат пока объединены в одном экране;
- поддерживается только PCM WAV, нет MP3/M4A и полноценной валидации;
- ошибки API не имеют единого технического кода;
- нет отдельного endpoint с информацией о модели.

### Приоритет 2

- нет Redis-очереди и отдельного worker;
- отсутствуют статусы асинхронной задачи и отмена;
- нет Room, DataStore, истории и настроек Android;
- Android-код не разделён на ViewModel, Repository и явные UI-состояния.

### Приоритет 3 и исследовательская часть

- нет импорта через системное меню «Поделиться» и визуализации волны;
- нет обученной модели, датасета, экспериментального скрипта и метрик качества;
- тесты пока покрывают только базовый WAV-анализатор.

## Модули, требующие изменения

- `android/app/src/main/res/` — строки RU/EN, темы и последующие ресурсы интерфейса;
- `android/app/src/main/java/ru/faith/app/` — экраны, навигация, ViewModel, Repository и аудио;
- `android/app/build.gradle.kts` — зависимости архитектуры и тестирования;
- `backend/app/main.py` и `backend/app/schemas.py` — контракт задач, ошибки и model info;
- `backend/app/audio.py` — декодирование, предобработка и подключение модели;
- `compose.yaml` и `backend/` — worker, окружения и production-настройки;
- `backend/tests/` и Android test source sets — API, ViewModel, Room и UI-тесты;
- `README.md` и `docs/` — запуск, архитектура, ограничения и защита.

## Этапы

1. Локализация RU/EN и сохранение первого выбора языка.
2. Разделение Android на главный экран, предпросмотр, обработку и результат.
3. Запись с микрофона, метаданные и безопасная валидация файла.
4. Улучшение API-контракта, единых ошибок и тестов.
5. История/настройки через Room и DataStore.
6. Redis worker и асинхронные статусы.
7. Подключение обученной модели и исследовательский отчёт с метриками.

После каждого этапа выполняются Android-сборка, доступные тесты backend, проверка репозитория и
обновление README. Рабочие функции сохраняются до появления проверенной замены.
