# Безопасность FAITH

## Реализовано в локальном прототипе

- максимальный размер загружаемого аудио ограничен;
- формат и содержимое записи проверяются до запуска модели;
- исходные аудиофайлы не сохраняются backend после обработки;
- повторные запросы ограничиваются через Redis;
- ответы содержат защитные HTTP-заголовки;
- административная панель закрыта HTTP Basic и отключена без переменных окружения;
- события входа, просмотра панели и анализа фиксируются без аудиоданных и IP-адресов;
- пароли пользователей хешируются PBKDF2-SHA256 с индивидуальной случайной солью;
- в PostgreSQL сохраняется только SHA-256 выданного access token;
- Android хранит токен с шифрованием через Android Keystore;
- Redis хранит временный результат анализа 15 минут по умолчанию;
- удаление аккаунта удаляет сессии, внешние идентификаторы, связи истории,
  связанные события аудита и результаты без оставшихся владельцев;
- Android запрещает резервное копирование данных приложения;
- незашифрованный HTTP разрешён только debug-сборке для локального компьютера;
- секреты и реальные пароли исключены из Git.

## Локальная административная панель

В личном `.env` задайте уникальные значения:

```dotenv
ADMIN_USERNAME=faith-admin
ADMIN_PASSWORD=use-a-long-unique-password
```

После пересборки backend панель доступна по адресу <http://localhost:8000/admin>.
Браузер запросит имя и пароль. Не используйте Basic-аутентификацию через публичный
HTTP: на VPS панель должна открываться только через HTTPS.

## Перед публикацией на VPS

1. Настроить домен и HTTPS через Caddy или Nginx.
2. Указать домен в `ALLOWED_HOSTS`, убрав `*`.
3. Сгенерировать новые пароли PostgreSQL и администратора.
4. Не публиковать порты PostgreSQL и Redis в интернет.
5. Включить ежедневное резервное копирование базы и проверку восстановления.
6. Ограничить SSH ключами, отключить вход root по паролю и включить firewall.
7. Настроить ротацию журналов и срок хранения аудита.
8. Опубликовать политику конфиденциальности и определить срок хранения метаданных истории.
9. Перед обновлением схемы выполнить резервную копию PostgreSQL и применить
   `backend/migrations/001_add_phone_auth.sql`.

Яндекс ID подключён через официальный Android LoginSDK. Публичный Client ID допустим
в Android, а backend обязан получить то же значение через `YANDEX_CLIENT_ID` и
проверить `client_id` профиля Яндекса. Client secret приложению не передаётся.
Google, VK и Apple в текущей версии скрыты и не имитируются. SMS и подтверждение
email потребуют отдельных провайдеров; их секреты должны храниться только в
переменных окружения backend.
